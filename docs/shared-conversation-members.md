# 公共群成员与已读详情状态

成员数据由插件 Browser 的 ConversationMembersStore 按当前账号/环境与 sourceKey 持有。成员抽屉、会话、@ 候选、角色判断只订阅同一份快照。Host 继续通过现有 source.members 提供授权后的完整投影，memberRef 是稳定的成员身份。页面只持有展开、搜索、选中与滚动等展示状态。

刷新按成员合并，保留未改变实体及未改变列表的引用。只有匹配群、成员唯一、total/activeCount 完整的成功快照可以删除缺失成员。错误保留已知数据；本地移除和事件失效提高更新代次，旧响应不能覆盖新变化。网络暂时仍读取完整快照，不能称为服务端增量同步。

公共入口合并并发请求及 180ms 内重复失效，复用 30 秒内的新鲜数据；每群只有一个在途刷新。失去最后订阅者或切后台取消工作，账号切换清空状态，运行实例变化重建基线。最多保留 20 个无人订阅的群、合计 20000 个闲置成员。超出容量按群淘汰，不截断群成员结果；活动数据受订阅生命周期约束。sourceRef 轮换会重新校验，但保留相同群的已有数据。

## 能力矩阵

| 面 | 范围与验证 |
| --- | --- |
| UI | 公共成员数据、差量合并、刷新及失败恢复；Store 和组件测试 |
| Host owner | 复用现有成员/已读服务，没有新增接口、授权或业务查询 |
| Tools | N/A：没有新增模型业务能力；现有 arkme_source_members 与已读 Tools 合同不变 |
| SDK | N/A：没有扩展公开接口；现有成员/已读方法保持原合同 |
| Client/Harness | 无原生桥、装配或生命周期协议变更，沿用 Browser module 载体 |

已读人员范围和状态仍由消息已读服务确定，不能由当前群成员名单推算。成员资料可复用，但私人备注不能被写入群公开 @ 名称。缺失展示资料不代表成员已离群。

## 后续接口条件

真正的网络增量同步需要后端版本游标、完整性与明确删除记录；仅有事件提示时仍校准完整快照。冷加载的备注分页扫描需要按用户集合查询或服务端补齐合同，不能靠延长 Browser 缓存解决。大群分页必须同时维护已加载范围和服务端总量；首个不完整页面不具备删除权限。这些接口演进不在本次纯客户端状态变更中伪造。

## 验证结果与剩余性能边界

- 公共 Store、Hook 与页面集成验证覆盖重复打开、sourceRef 轮换、成员增删改、失败保留、权限撤销、乱序响应、账号切换及关闭取消。
- 1000 人、两个订阅组件的测试中，修改一名成员只触发该成员在两个组件中的行渲染，其他成员对象与行不变。
- 使用官方 DSH 0.1.1-rc.2、新 Profile 和打包插件完成 Browser 页面验收，业务响应/事件使用隔离合成数据：200 人群进入后打开抽屉共 1 次 source.members；刷新一名成员后 200 个 DOM 行复用，scrollTop 保持 500；移除后显示 199 人；错误保留 199 人并可重试；已打开的已读名单收到事件后更新，只增加 1 次详情调用。最终插件包另验证 500 人完整显示、打开抽屉不重复请求。
- 上述 UI 数据响应不代表真实后端、数据库或生产网络性能，也没有替换已安装客户端或发布制品。

500 人工作负载另通过真实 ChatService、ProfileService、SourceService、ServiceRuntime 与请求协调器运行，使用 fake clock 和合成上游。每次上游耗时固定 2000ms、备注目标未在前 20 页会话目录中找到：冷加载为成员请求 1 次、公开资料 10 批、目录 20 页，模拟累计 42000ms；公开资料暖缓存为 1 + 0 + 20 次，仍累计 42000ms。每个上游请求都低于 30000ms 单次超时，但整个 Host 操作没有因此被限制在 30 秒以内。此结果用于暴露串行依赖，不是生产耗时或性能达标证明。

公开 Chat members/list 在所核对的后端 master 9f649eac 中仍只有 chat_session_uid / active_only 参数及 items 响应，没有 limit、cursor、has_more；不能添加虚构的客户端分页循环。启用入群事件时还会请求非活跃成员，因此活跃人数上限不等于实际扫描总量。后端已有批量补昵称、备注，联系人身份快照则属于内部接口，不能作为插件公开查询直接使用。

本轮已交付公共成员状态和增量渲染、已读详情刷新；冷加载依赖、服务端真实分页和 DOM 虚拟化仍是下一阶段。它们需要把完整性、首批展示和资料补齐合同一起落实，不能把“只发一次 source.members”当作完成了 500 人性能优化。
